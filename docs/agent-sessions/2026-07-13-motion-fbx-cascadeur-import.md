# Motion FBX Cascadeur Import

Date: 2026-07-13

## Goal

Diagnose and fix the exported `motion.fbx` that Cascadeur rejects, and verify
whether Blender reports the same failure.

## Context

- Reproduction file: `E:\del\motion.fbx`
- Cascadeur reports `Failed to import FbxScene`, followed by rig-mode script
  error `Please select joints related to selected rig info`.
- The intended transport is an animation-only skeleton FBX generated by the
  Rust motion interchange backend.

## Progress

- Confirmed the original file is binary FBX 7.4 with 44 bones and one animation
  stack. Both Blender 4.2.1 and 5.1.2 import it successfully.
- Cascadeur 2026.1.3 fails inside its native `FbxContext` before rig hierarchy
  processing. The later Rig Info exception is secondary cleanup behavior.
- The original file omits standard scene/time/take metadata including
  `FileId`, `CreationTimeStamp`, `SceneInfo`, `TimeMode`, time span, and `Takes`.
- Added these nodes only to the animation-only FBX writer. The model FBX path
  remains unchanged.
- Rewrote the real source as `E:\del\motion_metadata_candidate.fbx` for direct
  application testing.
- Captured review evidence from the real applications under
  `docs/agent-sessions/assets/2026-07-13-motion-fbx-cascadeur-import/`.
- Confirmed that Cascadeur still rejects the metadata-only candidate during its
  native `FbxScene` load. Per user direction, further Cascadeur parser work was
  stopped in favor of Blender normalization.
- Connected to the live Blender 5.1.2 scene through Blender MCP. The current
  model armature and imported motion armature both contain the same 44 bone
  names and identical parent hierarchy. Their rest matrices differ by at most
  `1.3126869e-6`.
- Bound action `001hito_001gundam_005gyan00_001_kakun10a_stk_air_fr` to the
  skinned model armature using its Blender 5.1 Action Slot. The two model meshes
  remain parented and modified by the model armature.
- Created a non-destructive export Action, shifted its keys from Blender import
  frames `1..40` to FBX export frames `0..39`, and exported the complete model
  to `E:\del\model_with_motion_blender51.fbx`. The source motion armature and
  source Action remain in the working scene and are excluded from the FBX.
- Extended `EXVS2-Easy-Blender-Tools` to version 1.4.0 with explicit **A Model**
  and **B Motion** object pickers. Shift-selecting two armatures remains
  supported through **Fill A/B from Shift Selection**.
- Added **Select A + Model Meshes**. It prepares the safe manual FBX selection
  without exporting.
- Per user direction, successful one-click binding now copies B's Action and
  Action Slot to A, then deletes the B object. Its armature data and source
  Action are also removed when they have no other real users.
- Redesigned addon version 1.5.0 around Blender-native child panels. **Motion**
  and **FBX Export** stay open; **Rigid Skin**, **Selection**, **Cleanup**, and
  **Maintenance** start collapsed. Long instructions were replaced with short
  status and export keywords.
- Inspected the user's later manual export at
  `E:\del\model_with_motion_blender51.fbx`. That version contains two exported
  armatures with 66 bones each. The expected skeleton has 44 bones; each
  exported armature contains 22 Blender-generated `_end` leaf bones.
- The duplicate armatures came from exporting without limiting the export to A
  and its meshes. The `_end` bones came from leaving **Add Leaf Bones** enabled.

## Verification

- The real candidate imports successfully in Blender 4.2.1 and 5.1.2 as one
  armature with 44 bones and the expected action.
- Blender now recognizes the intended 60 FPS and frames 1 through 45. The old
  file fell back to 25 FPS and frames 1 through 19.3333 because `TimeMode` was
  absent; both represent the same 0.7333-second duration.
- Comparing all 45 frames and 44 pose-bone matrices gives a maximum component
  difference of `1.1026859e-6`; bone names, 440 curves, and 19,800 keys match.
- `cascadeur-original-import-error.png` captures the original Cascadeur 2026.1.3
  native import failure and the secondary RigInfo exception.
- `blender-5.1-candidate-import.png` captures Blender 5.1.2 after importing the
  real fixed candidate; the image includes the action and imported statistics.
- `cargo test --test ssbh_motion_interchange_test --no-fail-fast`: 11 passed,
  1 ignored.
- `cargo build`: passed with one pre-existing dead-code warning.
- Direct model/motion binding checks at corresponding frames `1->0`, `20->19`,
  and `40->39` have zero pose-matrix delta.
- The complete FBX was re-imported into an isolated Blender 5.1 scene. It
  contains one 44-bone armature, two meshes whose parent and Armature Modifier
  point to that armature, a 60 FPS action spanning frames `1..40`, and finite
  sampled pose matrices.
- `blender-complete-model-motion.png` captures the live skinned model at frame
  20 after the verified binding.
- Blender 5.1 loaded addon version 1.4.0 and registered all three new operators.
  The live scene resolved Shift selection to `A=Armature` and
  `B=Armature.001`; the safe-selection operator selected only `Armature`,
  `SHAPE_ROOTShape`, and `SHAPE_ROOTShape__sub1`.
- `blender-motion-bind-ui-v1.3.png` captures the installed A/B pickers, Shift
  selection action, validation state, and manual FBX export checklist.
- `blender-motion-bind-ui-v1.4.png` captures the installed destructive-binding
  warning that successful binding deletes B Motion.
- Re-import inspection of the contaminated FBX finds two 66-bone armatures and
  four animation Actions. Their rest poses differ, so the addon correctly
  refuses to bind that already-contaminated export.
- Blender 5.1 integration testing imported the real `motion.fbx` twice and used
  a mesh Armature modifier to identify A. After one-click binding, only
  `Armature` remained; `Armature.001`, its unused armature data, and its source
  Action were removed. The copied model Action spans frames `0..39`.
- Blender 5.1 registered all seven version 1.5.0 panel classes with the intended
  open/closed defaults. The real-file one-click workflow still finishes with
  one armature and an Action spanning frames `0..39`.
- `blender-easy-tools-layout-v1.5.png` captures the installed compact component
  layout and export keyword checklist.
