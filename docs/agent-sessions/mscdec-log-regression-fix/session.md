## Root Causes

### Missing grouped condition operands

`mscdec.py` decompiles expressions backwards with a module-level `index`.
Some nested empty branches generated by `pullOutGroups()` do not own a pushed
condition. `getArgs(1)` continued scanning through the enclosing loop, consumed
the caller's index, and eventually asked binary opcode `0x27` for two operands
when none remained.

The fix introduces `MissingArgumentsError`. An `IfElseIntermediate` that has no
condition restores the original function and index before being ignored. Other
index errors are not swallowed.

### Nested loop stack metadata

`pullOutGroups()` derives an if-expression's `pushBit` from its final nested
item. A `WhileIntermediate` can legally be that item, but the class did not
define `pushBit`.

The fix defines `WhileIntermediate.pushBit = False`, matching loop semantics:
a loop statement does not produce an expression stack value.

### Recursive path explosion

The active decompiler still called legacy `emuScript()`, which recursively
explored control-flow paths and used arbitrary 2,000/10,000 iteration limits.
One logged file reached the hard failure.

The existing CFG resolver could not be used directly because its strict
`msc_core.Command` checks rejected legacy `mscdec_msc.Command` objects.
Delegating to `disasmlib_ref_only` avoided the exception but produced nearly
empty C functions due to the same type mismatch.

The fix makes `msc_cfg.py` accept command-like objects and an injected opcode
stack-pop table. `disasmlib.py` now runs CFG resolution on the active legacy
objects, and `mscdec.py` explicitly selects that path.
