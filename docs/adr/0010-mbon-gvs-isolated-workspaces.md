# Isolated MBON and GVS workspaces beside Over Boost

Status: accepted (2026-10-01)

The author asked for PS4 **MBON** (Mobile Suit Gundam Extreme Vs. Maxi Boost
ON, CUSA15006) and PS4 **GVS** (Gundam Versus, CUSA08379) modding support.
Both titles are **earlier** than Over Boost, so they sit inside the
"OB and earlier" scope of `ACCEPTABLE_USE.md`. Nothing here touches a
later-than-OB revision.

## Decision

1. **Hard isolation from OB.** MBON and GVS live in their own Rust crates and
   their own frontend folders. OB modules do not import them and they do not
   import OB modules. The only shared touch points are composition-root
   wiring: Cargo workspace members, Tauri command registration in `lib.rs`,
   and route entries in the router / sidebar.

   | Layer | OB (unchanged) | MBON | GVS | Shared by MBON + GVS only |
   | --- | --- | --- | --- | --- |
   | Rust domain | `src-tauri/src/**` | `src-tauri/crates/mbon` (`exvs_mbon`) | `src-tauri/crates/gvs` (`exvs_gvs`) | `src-tauri/crates/ps4_common` (`exvs_ps4_common`) |
   | Tauri adapter | `src-tauri/src/*commands*` | `src-tauri/src/mbon/` | `src-tauri/src/gvs/` | none |
   | Frontend | `src/page/**` | `src/games/mbon/` | `src/games/gvs/` | `src/games/ps4-common/` |

   `ps4_common` exists because both PS4 builds wrap every `archives/XX/*.bin`
   file in the same `99 92 CD 90` container (the uncompressed sibling of the
   OB FHM2D container). It contains no game semantics.

2. **Research sources.**
   * MBON: every format finding comes from descatal's **BoostStudio**
     (<https://github.com/descatal/BoostStudio>). BoostStudio ships no
     license file, so this project does not copy its code; the Rust readers
     are independent implementations of the documented layouts, credited in
     every MBON source file, manifest and UI panel.
   * GVS: support is the author's own result, derived from this project's
     VS2 / Over Boost research (FHM2D, nutexb, SSBH families).

3. **Provenance notices.** Every MBON / GVS / PS4-common source carries a
   unique file-top notice generated by `tools/stamp_mbon_gvs_notices.py`
   (`--check`, `--write`; no `--strip`). Wording, language mix, length,
   wrap width and comment style are derived from the file path, extending
   SourceNoticeCanary (ADR 0008) to these trees. Notices always name
   kjjkjjzyayufqza; MBON notices always credit descatal / BoostStudio.
   Rust tests and a vitest test fail when a notice loses its credits.
   The two MBON / GVS Python tools (`tools/build_ps4_name_tables.py`,
   `tools/stamp_mbon_gvs_notices.py`) carry `#` notices from the same
   generator. The generated name tables start with a credit header that is
   compiled into the app with the table; the crates' provenance tests check it.

4. **Game files stay local.** Samples used for TDD are UnlicensedGameMaterial.
   They live under the gitignored `tmp/` tree (or wherever
   `EXVS_MBON_SAMPLES` / `EXVS_GVS_SAMPLES` point). Tests skip when they are
   absent. Repacked outputs are written outside git as well.

5. **OB workflow parity (2026-10-01).** Data init, single-archive unpack /
   repack and "repack changes" follow the OB FHM2D Init, Single FHM2D and
   repack dialogs:

   * Archives are named from per-game tables embedded in the crates
     (`crates/{mbon,gvs}/data/*_names.tsv`, generated by
     `tools/build_ps4_name_tables.py`). Both PS4 builds reuse the VS2-era
     path hashes for their shared global tables; GVS reuses them for unit,
     effect, GUI and sound packs too. MBON adds BoostStudio's
     `ExvsCommonAssets` hashes. The tables hold hashes and names only.
   * Packages extract into `route/name` folders below the workspace and are
     discovered at any depth (`exvs_ps4_common::workspace`).
   * Repacks without an explicit output go to a per-game mod folder that
     mirrors the game root (`archives/XX/HASH.bin`, default
     `<workspace>/_out`).
   * Each package keeps a change baseline (`*.state.json`: size and
     modification time of every tracked file plus the manifest digest),
     refreshed after extraction and every repack, so pending edits are
     listed without reading data. Extraction never clears a folder that is
     neither empty nor a package.
   * Routes `/MbonSingleFhm` and `/GvsSingleFhm2d` join the composition-root
     touch points (router, sidebar URL list, full-bleed list).

   User guide: `docs/mbon-gvs/README.md`.

## Consequences

* OB behaviour cannot regress through MBON/GVS work: the crates compile
  independently and the OB modules have no new imports.
* `cargo test -p exvs_ps4_common -p exvs_mbon -p exvs_gvs` runs the PS4 suites
  without building the Tauri shell.
* Removing a credit or an author handle breaks `stamp_mbon_gvs_notices.py
  --check` and the provenance tests.
