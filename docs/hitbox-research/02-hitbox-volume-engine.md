## 0. 结论（全部由二进制证实）

一行 hitgroupiddef 定义**一个球**（`vdkSpheref`，vftable `0x141342EF8`）：

```
球心(骨骼空间) = ( 0x8B1AA53F , 0xFC1D95A9 , 0x6514C413 )   ← X, Y, Z(前向)
球半径         =   0xDC8AC901
挂载骨骼       =   0xD32D39ED    （actor 由 0xEDD1C108 决定）
```

**现有命名 `radius` / `scale_x` / `joint_offset` / `group_id` 四个全是错的。**
真正的半径是被叫作 `group_id` 的那个 f32（值域 2 / 2.5 / 3.5 / 6 / 7 / 8）；
被叫作 `radius` 的那个是**前向偏移 Z**。

每帧球心被该骨骼的 4×4 世界矩阵变换（半径不参与变换）。当
`0x7395D184 == 1` 时，引擎在**上一帧球心**与**本帧球心**之间构造**扫掠胶囊**。

> **对用户直觉的裁决：CONFIRMED，但需修正一处。**
> 光剑的判定**不是**沿刀身预先摆好的一根长胶囊，而是**若干颗球**（强人半径 6–8，
> 前伸 6–20），其"刀光"体积由**动画逐帧扫掠**生成。所以横砍确实只覆盖一条横向弧线，
> 上下方向的覆盖仅为 `r_攻击 + r_受击`。**绝不是 AABB**——轴对齐盒只用于宽相剔除。

## 1. 通用 param 访问器

```
LookupCommandDescriptorByHash  @ 0x1401A8BD0
```

对 `paramFile + 0x20` 处已排序 u32 hash 数组做 lower_bound 二分（个数在 `+0x14`），
返回 `hashArrayEnd + 12 * index` 处 12 字节描述符；字段值 = `*(row + descriptor.entryOffset)`。
全二进制 **71 处 xref / 约 30 个函数**。`DamageDispatcher` 经包装器 `sub_1405F8C00` 到达。

### 1.1 方法学修正（后续逆向请直接采用）

研究开始时我判断「param 字段 hash 不以立即数出现在 exe 中」——**这是错的**，
并且这个错误判断被写进了给各战线的简报里，是本次研究中我犯的最大方法学错误。

访问器通常被**内联**成两条 `cmp` 的二分查找，hash 确实以 imm32 出现；
只是 IDA 的 `find(type=immediate)` 查不到它们。

> **正确做法：`find_bytes` 搜 hash 的小端 4 字节。**
> `0x6514C413` → `13 C4 14 65`；`0xC3656A99` → `99 6A 65 C3`。
> 对照验证：`find(immediate)` 对 `0x6514C413` 返回 0 命中，
> `find_bytes` 在 `sub_140667740` 内精确命中 `0x1406678C2` / `0x1406678E8`。

## 2. 球的构造：`sub_14066A8E0`

```c
// 0x14066A9AB —— 打包球心 float4 = [0x8B1AA53F, 0xFC1D95A9, 0x6514C413, 0]
a2[1] = _mm_unpacklo_ps(
            _mm_unpacklo_ps(get(0x8B1AA53F), get(0x6514C413)),
            _mm_unpacklo_ps(get(0xFC1D95A9), 0));
// 0x14066A986 —— 半径写入 sphere+32
a2[2].m128_i32[0] = get(0xDC8AC901);
```

专用 getter（每个内部各含一份内联二分）：

| Hash | getter | hash 比较站点 |
|---|---|---|
| `0x8B1AA53F` | `sub_140668A30` | `0x140668A6B` |
| `0xFC1D95A9` | `sub_140668AF0` | `0x140668B2B` |
| `0x6514C413` | `sub_140668BB0` | `0x140668BEB` |
| `0xDC8AC901` | （经 `sub_140668C70`） | — |
| `0x7395D184` | `sub_14066A780` | `0x14066A7BB` |
| `0x11E501D5` | `sub_14066B840` | `0x14066B87B` |

### 2.1 ★ 决定性证据：引擎内置的默认近战 hitbox

当某机体对当前 group 没有任何行时，`sub_140669D30` 的 else 分支使用硬编码默认值：

```
0x14066A231:  v78    = 1088421888          // = 7.0f  半径
              v77[1] = xmmword_141347DB0
0x141347DB0:  00 00 00 00 | 40 00 00 00 | 41 88 00 00 | 00 00 00 00
              =  { 0.0 , 2.0 , 17.0 , 0.0 }
```

一个球心 (0, 2, 17)、半径 7.0 的球——**X=0（不偏左右）、Y=2（略高）、
Z=17（前伸 17）、r=7**。这与近战默认判定应有的形状完全吻合，
独立锁死了三个分量的车道映射与半径归属。

## 3. 放置：骨骼世界矩阵变换

`sub_140669D30`：

1. 读 `0xD32D39ED`（`0x140669E67`）—— 这是**骨骼 ID**，不是"父骨骼哈希"。
2. 在骨架 `+184` 的 bone-id→index `unordered_map` 中查表（`0x140669F00` 调 `0x1402FB3E0`）。
3. 从 `骨架 +112` 的矩阵数组取第 `idx` 个 **64 字节 4×4 世界矩阵**（`0x140669F15`–`0x140669F3A`）。
4. `sub_14066AD30` → `sub_1400C7EA0` 做完整的点×矩阵变换（含平移行 `a3[3]`）；
   **半径原样拷贝，不参与变换**（`0x14066AD47` → `0x14066AD6D`）。

Actor / 模型由 `0xEDD1C108` 经 `sub_14066A830`（hash 比较 `0x14066A86B`）→ `sub_14035D820` 解析——
这决定用**哪具骨架**。

## 4. 扫掠：`0x7395D184` 决定静态球还是运动胶囊

`sub_14066A2C0` 逐行读 `0x7395D184`，把模式 1/0 写进槽向量 `a1+72`，
并在 group 激活时把**上一帧缓存的半径清零**。

`sub_140669D30`（`0x140669F4F`–`0x140669FD1`）当模式 == 1 时：

```
若 上一帧半径 > 0  →  端点 A = 上一帧球心，端点 B = 本帧球心   （胶囊）
否则               →  A = B = 本帧球心                        （退化为球）
随后把本帧球心写回上一帧缓存
```

所以**激活后的第一帧必然是静态球**，之后才逐帧形成扫掠胶囊。
`sub_1406868C0` 按该标志分派：`1` → `sub_140347370`（胶囊测试），`0` → `sub_140346E00`（球测试）。

### 4.1 窄相记录布局（64 字节，近战与弹丸共用）

```
+16  端点 A (float4)
+32  端点 B (float4)
+48  半径
```

弹丸用同一结构：`sub_140DDA1B0` 用位置轨迹填 A/B，
半径 = `*(float*)(projectileParam + 44) * 0.5`。**近战与射击共享同一套扫掠球图元。**

## 5. 相交测试

### 5.1 球 vs 球（`sub_140346E00 @ 0x140347100`）

```c
v30 = _mm_and_ps(_mm_cmplt_ps(dist2_4wide, _mm_mul_ps(rSum, rSum)),
                 *(__m128*)(leaf + 64));      // 逐球 enable 掩码
```

即 `dist² < (r_攻 + r_受)²`，SIMD 一次算 4 个受击球（SoA）。
另有 owner 过滤避免自伤（`0x140347173`）。

### 5.2 胶囊 vs 球（`sub_140347370`）

标准的**线段-点最近距离三分支**，比较对象为 `(r_sum)²`：

```
t = dot(P - A, B - A)
t < 0            →  |P-A|² < r_sum²
t > |B-A|²       →  |P-B|² < r_sum²
否则             →  |P-A|² - t²/|B-A|² < r_sum²
```

当 `|B-A|² <= 0.001`（epsilon 位于 `0x141B4F620` = `0x3A83126F` = `0.001f`）时，
退化为球测试并尾调用 `sub_140346E00`。

### 5.3 受击球全局池

位于 `qword_14241E920 + 33216`：**512 个 leaf × 4 球 = 最多 2048 个**，
每 leaf 80 字节 SoA：

| 偏移（leaf 内） | 全局偏移 | 内容 |
|---|---|---|
| +0 … +47 | — | x4, y4, z4 |
| +48 | **+41488** | radius4 |
| +64 | **+41504** | enableMask4 |
| — | +49696 | owner ID |

三级 SIMD AABB 层次剔除：8 / 32 / 128 节点 × 112B，位于 `+100480` / `+96864` / `+82496`。
**AABB 只用于宽相剔除，不是判定形状本身。**

## 6. 三个类别：`collision_flags` 是行的类别（Class A/B 假设已证实）

`sub_140667740` 按 `collision_flags` 把行分桶（`bucket = &a1[8 * collision_flags]`，
`0x1406679B4`–`0x1406679C3`），并用**不同的键**做 FNV-1a 索引：

| collision_flags | 索引键 | 语义 | 证据 |
|---|---|---|---|
| **0** | `0xC3656A99`（interaction 外键） | **攻击判定** | 由 `sub_14066A2C0` → `sub_14066B090(ctx, 0, key)` 按键激活 |
| **1** | `0xEDD1C108`（model_hash） | **机体被弹判定 hurtbox** | 经 `sub_140669060` / `sub_140669710` 用骨骼矩阵送进全局池 |
| **2** | — | 第三类，Gyan 无 | 经 `sub_14066B750` → `sub_14066B090(ctx, 2, key)`；`hit_type == 1` 只出现在这一类 |

**这就在二进制层面证实了 01 号文档的核心推断：**
MSC 用 `func_148(interactionId)` 武装攻击 → 引擎以该 ID 为键查 class-0 表 → 取出所有外键匹配的行 → 那些就是本帧的攻击球。

攻击侧激活入口：`sub_140681910`（`sub_14066A2C0` 的唯一代码调用者，`0x140681C60`）。

### 6.1 无敌帧就是把 hurtbox 关掉

```c
sub_140633EB0:  sub_140669060(a1 + 215952, (*(BYTE*)(a1 + 1300) & 0xC) == 0, ...);
```

`(statusFlags & 0xC) != 0` 时整组受击球的 enable 掩码写 0。
另外受击球半径在入池前会乘以 `controller + 76` 处的 f32（疑似机体体型系数，未证实）。

## 7. 死字段：**5 个**字段引擎从不读

| Hash | 现有命名 | 状态 |
|---|---|---|
| `0x42EE5CA2` | offset_y | 全二进制 **0 次**出现 |
| `0x458398BB` | offset_z | 仅作为数据出现在 `dword_141347C90` 表内 |
| `0x3284A82D` | offset_x | 同上 |
| `0xACE03D8E` | scale_y | 同上 |
| `0xDBE70D18` | scale_z | 同上 |

`dword_141347C90` = `{0xDC8AC901, 0x458398BB, 0x3284A82D, 0xACE03D8E, 0xDBE70D18}`，
其唯一消费者 `sub_140668C70` 的唯一调用点 `0x140669A2C`（在 `sub_140669710` 内）
**永远传索引 0**，即只取 `0xDC8AC901`（半径）。后四个从未被取用。

> 编辑这 5 个字段对游戏行为**没有任何影响**。数据侧统计也印证：全语料 1435 行中它们恒为 0.0。

`hit_type (0x11E501D5)` 不参与体积构造：每个激活的 group 只从**最后一行**读一次，
存到 hit controller `+128` 供后续命中判定使用（`sub_14066B750 @ 0x14066B7E5`）。

## 9. 单位

**没有任何单位换算常数。** 球心经骨骼世界矩阵后直接使用，半径在攻击侧原样比较，
仅受击侧乘 `controller+76`。装载与使用路径上都找不到 `*0.1f` / `*100.0f` 之类的缩放。

因此 Z 偏移 6–20、半径 2–8 就是**引擎世界单位**。
换算到"米"需要一个已知尺寸锚点（渲染器/相机/模型实测），**目前 UNPROVEN**。
