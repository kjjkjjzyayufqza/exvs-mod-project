# EXVS MSC Syscall 54 Investigation Notes

## 概述

这份文档记录当前针对 `sys_54`（`0x54`）的阶段性分析结果，重点回答它在游戏里“具体控制了什么镜头行为”。

建议结合以下文档一起阅读：

- `docs/exvs-msc-analysis.md`
- `docs/exvs-msc-syscall-53-notes.md`
- `docs/exvs-msc-syscall-4e-notes.md`

---

## 当前最强结论

基于 `CDepictionScript` 挂载函数 `sub_140664F70`：

- `a1[88] = sub_140683070`（data xref: `0x140665096`）
- 映射模型：`syscall_id = slot_index - 4`
- 因此：`slot 88 -> syscall 84 -> sys_54 -> sub_140683070`

`sys_54` 与 `sys_53` 一样都属于镜头/depiction family，但角色不同：

- `sys_53` 偏 preset 启停与多通道插值
- `sys_54` 偏 **相机朝向、角度限制、状态切换**

---

## Native Handler 形态

`sub_140683070` 特征如下：

- 入口签名：`(__int64, __int64, int, _DWORD *)`
- 主对象：`v8 = *(_QWORD *)(*(_QWORD *)(a2 + 40) + 10808)`（镜头控制结构）
- 分发方式：`switch(*a4)`（`0x0 ~ 0x3`）

即 `sys_54` 当前可见有 4 个子命令：

- `subcmd 0x0`（主启动）
- `subcmd 0x1`（停止/复位）
- `subcmd 0x2`（角度参数写入）
- `subcmd 0x3`（比例/速率参数写入）

---

## “它控制了什么”的证据链

### 证据 1：`subcmd 0x2` 明确写“角度（弧度）”

`subcmd 0x2` 将 `a4[1], a4[2]` 经过：

- `/100.0f`
- `* PI / 180.0f`

再写入 `v8 + 144`、`v8 + 148`。

这就是标准“百分制角度输入 -> 弧度”转换，不是通用倍率参数。

### 证据 2：`subcmd 0x3` 写入非角度比例字段

`subcmd 0x3` 仅 `/100.0f` 后写到：

- `v8 + 152`
- `v8 + 156`

这组值没有走弧度转换，更像权重/速率/阻尼类系数。

### 证据 3：`subcmd 0x0` 会初始化并装载角度边界

`subcmd 0x0` 在激活分支中会：

1. 从 `+10680 + 384` 取当前向量作为初始姿态，调用 `sub_140626A90` 初始化结构；
2. 调 `sub_140626B70(v8, 1)` 切到 active；
3. 可选参数控制方向模式（`-1/0/1`）；
4. 当第 4 参数为 `1` 时，装载一整组角度配置：
   - `v8+144/+148`（主角度）
   - `v8+160/+164`（镜像/第二组角度）
   - `v8+128/+132/+136/+140`（四个角度边界）
5. 同时清零若干状态计数（`+112`, `+120`, `+152`）。

默认边界常量可读成约：

- `+60°`
- `-65°`
- `+113°`
- `-113°`

这非常符合“镜头可转动范围/夹角限制”的语义。

### 证据 4：`subcmd 0x1` 是停用并回写姿态

`subcmd 0x1` 在满足状态条件时会把 `v8+48` 回写到：

- `+10680 + 384`
- `+10680 + 448`

随后 `sub_140626B70(v8, 0)` 关闭该模式。

这是典型“退出镜头模式并同步最终姿态”的流程。

## 脚本侧调用模式（2.c）

`sys_54` 在脚本中出现非常集中：

- 全局重置点：`sys_54(0x1)`（开场/分支重入时）
- 配置点：`func_271(...)` 连续调用
  - `sys_54(0, arg0, arg1, 0x1, var9, var10)`
  - `sys_54(0x2, var11, var12)`
  - `sys_54(0x3, var13, var14)`

其中 `var9..var14` 来自 `sys_0(0xb0005, hash)`，且按 `arg2` 选择不同 hash 组。

这说明 `sys_54` 常用于“按场景/形态切换镜头参数包”，不是每帧临时计算。

## 子命令语义（当前版本）

### `subcmd 0x0`（高置信）

- 启动一套镜头控制状态（active mode）
- 可选设置方向模式与角度边界
- 可装载扩展角度配置（第 4 参数为 `1`）

### `subcmd 0x1`（高置信）

- 关闭该镜头模式
- 可在关闭前回写当前姿态到公共相机向量缓存

### `subcmd 0x2`（高置信）

- 写入两轴角度（输入是百分制角度，内部转弧度）

### `subcmd 0x3`（中高置信）

- 写入两项比例/速率参数（仅 `/100`，不转弧度）

---

## 结论（当前版本）

`sys_54` 在游戏内主要控制：

- 特定镜头模式的启停
- 镜头两轴角度参数
- 镜头旋转/偏转边界
- 一组角度相关比例参数（疑似平滑/响应度）

它和 `sys_53` 一起构成演出镜头控制的两层接口：

- `sys_53`：preset 与多通道插值
- `sys_54`：姿态与角度限制

## 仍待确认的问题

- `subcmd 0x3` 的两项参数是“角速度限制、阻尼、还是插值速度”。
- `subcmd 0x0` 的 `arg0/arg1` 在不同镜头状态中的优先级关系。
- `+104/+108`（来自 `sub_1406824F0 / sub_1406825B0`）对应的具体键值语义。
