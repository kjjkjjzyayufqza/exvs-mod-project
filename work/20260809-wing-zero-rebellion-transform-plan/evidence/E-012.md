# E-012 — CS action-entry charge consumption

Date: 2026-08-22  
Status: source and target 2.dscex verified; in-game confirmation pending

## Runtime finding

The user reported that a completed CS action remained immediately reusable.
Action selection and playback did not consume the native full-charge state.

## Root cause and ownership

- Normal CSA, directional CSA, and bird CSA all read the shared slot-0 charge
  state but none cleared it at action entry.
- `sys_4F(0xA,0)` is the native charge accumulator reset for slot 0.
- Bird main and bird CSA share `ACTION_A_SHOT_BIRD`; the clear must remain in
  `ACTION_CHARGE_SHOT_BIRD` so uncharged main does not clear CSA.
- CSB already calls `func_1031()` at entry, which consumes/disables slot 4 via
  `sys_4F(0x11,4,0)`, `sys_4F(0x5,4,0)`, and `sys_4F(0x3,4)`.

## Lifecycle

| Phase | Policy |
|---|---|
| ENTER | consume the selected CS charge slot once |
| ACTIVE | no per-tick charge writes |
| EXIT | do not restore the full-charge state |
| INTERRUPT | do not restore; cancelled startup still spent the charge |
| RESPAWN | native loadout initialization reconstructs the slots |

## Change

`sys_4F(0xA,0)` now precedes the continuation in:

- `ACTION_CHARGE_SHOT`
- `ACTION_CHARGE_SHOT_DIRECTIONAL`
- `ACTION_CHARGE_SHOT_BIRD`
